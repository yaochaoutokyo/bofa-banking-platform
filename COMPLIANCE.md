# Compliance mapping — controls, code, and coverage gaps

This document connects each compliance-critical service and its *untested*
edge cases to the regulation or control they support, so that a coverage gap
can be read as a potential examination finding and a new test can be read as
control evidence.

Coverage figures are regenerated by `python3 scripts/coverage-summary.py`
and shown in the README's *Compliance Readiness* table. Targets are set in
[`.codecov.yml`](.codecov.yml).

## Service-by-service mapping

### transaction-service — Java · compliance-critical · target 90%

Coverage today: ~16% lines, happy-path only. Every item below has **no test**.

| Untested edge case | Where | Control / regulation | Finding if it fails |
|---|---|---|---|
| Negative transfer amount accepted | `TransactionService.transfer` | SOX 404 completeness & accuracy; Reg E unauthorised transfer; OCC *Internal Control* | Funds move in the reverse direction without authorisation |
| Zero-amount transfer accepted | `TransactionService.transfer` | SOX 404; operational risk | Phantom transactions pollute the ledger and audit trail |
| `BigDecimal` scale / overflow not bounded | `TransactionService`, `BatchTransferService` | SOX 404 accuracy | Precision loss or exception on high-value / high-precision inputs |
| Currency mismatch between accounts | `TransactionService`, `CurrencyConverter` | SOX 404; OCC *Foreign Exchange* | Cross-currency posting without conversion |
| FX rounding uses `double` and truncates minor units | `CurrencyConverter.convert` | SOX 404 accuracy; customer harm (UDAAP) | Systematic sub-cent errors, biased against one party |
| Idempotency key reused with different payload | `TransactionService` idempotency cache | Payments integrity; PCI-DSS 6 secure design | Replay with altered amount returns the original success |
| Partial failure: destination credit fails after source debit | `TransactionService.transfer` | SOX 404; OCC operational risk | Money leaves one account and reaches nowhere; rollback exceptions swallowed |
| Batch rollback failures swallowed | `BatchTransferService` | SOX 404 | Batch reports success while individual legs failed |
| Reg E dispute window, provisional credit deadline (10 business days), 45/90-day resolution | `DisputeService` | Reg E §1005.11 | Missed statutory deadlines with no alert |
| Daily / per-transfer limits, dual approval > $50k, self-approval | `LimitPolicyService` | OCC *Internal Control* — segregation of duties; BSA structuring | Unapproved large transfers; an approver approving their own override |
| Sanctions screening on counterparties | `SanctionsScreeningService` | OFAC | Payment to a blocked party |
| Holds and scheduled transfers | `HoldService`, `ScheduledTransferService` | Reg CC; Reg E | Funds availability errors |

## How to use this document in a review

1. When a test PR lands, copy the row(s) it covers into the PR's *Compliance
   impact* section.
2. If a test exposes a defect, the "Finding if it fails" column is the
   plain-English description for the risk register.
3. Rows with no test are candidate examination findings; prioritise by the
   regulation column, not by service size.
